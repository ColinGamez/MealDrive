# MealDrive

[![Quality](https://github.com/ColinGamez/MealDrive/actions/workflows/quality.yml/badge.svg)](https://github.com/ColinGamez/MealDrive/actions/workflows/quality.yml)

MealDrive is a multilingual AI kitchen assistant that turns pantry ingredients into practical recipes, weekly meal plans, and shopping lists.

## Highlights

- Scan a fridge image and add detected ingredients to the pantry.
- Generate recipes and seven-day meal plans from available food.
- Track quantities, low-stock items, saved recipes, cooking history, and streaks.
- Export shopping needs through Instacart, Rakuten, or Naver based on locale.
- Use English, Japanese, or Korean throughout the interface.
- Keep kitchen data private in namespaced local browser storage.

## Local development

Requirements: Node.js 22 or newer.

```powershell
npm install
Copy-Item .env.example .env.local
npm run dev
```

The unified Vite and Express server runs at `http://localhost:3000`.

Set `GEMINI_API_KEY` in `.env.local` to enable fridge analysis, recipe generation, meal planning, meal swaps, and speech generation. The server loads `.env.local` before `.env` while preserving any variables supplied by the host. Shopping-provider credentials are optional.

## Quality checks

```bash
npm run lint
npm test
npm run build
npm run smoke
npm start
```

`npm run lint` performs a strict TypeScript compile check. The test suite covers API health, security headers, rate limits, validation, credential boundaries, ingredient math, pantry and shopping merges, storage behavior, and translation completeness across all supported languages. `npm run smoke` boots the compiled production server and verifies both its API and application shell. GitHub Actions runs the complete gate for every pull request.

## Architecture

- `src/` — React 19 interface, local state, i18n, and kitchen utilities.
- `server/` — Express API routes that keep provider credentials off the client.
- `public/` — app metadata and optimized visual assets.
- `dist/` — production output generated by Vite.

Heavy secondary screens are loaded on demand so the dashboard remains the smallest initial route.
